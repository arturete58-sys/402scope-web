What you get

Four things a facilitator cannot see on its own

Each one works alone. Together they turn your facilitator into the one buyers and agents prefer to pay through.

01 · Every payment

A verdict on the seller, at verify and settle

Before you verify or settle, the seller behind the payTo is checked against independent measurements. Flag it for your logs, or block it. Works for exact payments and for prepaid batch-settlement ledgers.

02 · Your catalogue

A Bazaar ranked by what actually works

Your discovery listing comes back with each seller’s measured score, trusted sellers first. Put it in front of your existing Bazaar with no change to it.

03 · Before your users notice

Alerts when a seller degrades

Watch the sellers in your network and get a callback when one crosses the fault bound you choose. Share what you settle, opt-in, and it gets measured too.

04 · Optional

Refunds when a seller breaks its own terms

Sellers can back their terms with a bond. If a response breaks what the seller declared, its own signed receipt is the proof and the buyer is refunded on Stellar, at once. You show those sellers first.

How refunds work

Install

One call on your facilitator

For any facilitator built on the official @x402/core. Open source, Apache 2.0. No key needed to start.

npm install github:arturete58-sys/402scope-trust

import { scopeFacilitator } from '402scope-trust/facilitator';

const scope = scopeFacilitator(facilitator, {
  trust: { chain },        // onchain attesters on Stellar, or { apiUrl }, or your own checker
  mode: 'flag',            // 'block' refuses sellers that are not trusted
  share: { apiUrl, key },  // optional: get what you settle measured
  refunds: { contract, rpcUrl, networkPassphrase, token },  // optional: label refund-backed sellers
});

const listing = await scope.rank(bazaarItems);   // trusted and refund-backed sellers first

Facilitators written in another language call the same checks over HTTP. The open-source API also accepts a login with the facilitator’s Stellar account (SEP-10) instead of a shared key.

Optional refunds

Refunded by a signature, not by a support ticket

A seller that opts in locks a bond in a contract on Stellar. Each paid response carries the seller’s signed receipt: what it delivered, how old the data was, and the maximum age it promised.

If the receipt shows the seller broke its own terms, the buyer’s client submits it and the contract refunds the payer in the same transaction. Nobody decides: the rule only reads what the seller signed.

Seller

Opts in, or not

A bond of a few dollars covers thousands of calls. It stays the seller’s: withdrawable after a notice period, lost only to its own broken promises.

Buyer

Gets the money back at once

The agent’s client checks every paid response and claims automatically. The refund goes to the payer named in the seller’s own receipt.

Nobody else

No one holds the funds

The contract has no admin. 402Scope publishes the code and counts refunds in its fault rates; it holds no money and decides no refund.
